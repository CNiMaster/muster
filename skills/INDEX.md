# Skills Index

按开发阶段分组，供 Leader 在 plan 模式下按需加载为 Worker 的 system prompt。

## 规划阶段
| Skill | 触发场景 |
|-------|---------|
| spec-driven-development | 需求不明确，需要先写规格 |
| planning-and-task-breakdown | 需求清楚，需要拆解任务 |
| idea-refine | 创意发散，需要结构化打磨 |
| context-engineering | 新会话启动，配置上下文 |

## 实现阶段
| Skill | 触发场景 |
|-------|---------|
| incremental-implementation | 多文件变更，需增量交付 |
| test-driven-development | 实现逻辑，先写测试 |
| source-driven-development | 依赖官方文档的正确性 |
| api-and-interface-design | 设计 API 或模块边界 |
| frontend-ui-engineering | 构建用户界面 |
| karpathy-guidelines | 一切编码任务的行事准则（假设显式化/极简/外科手术式修改/目标驱动） |

## 验证阶段
| Skill | 触发场景 |
|-------|---------|
| code-review-and-quality | 合并前代码审查 |
| security-and-hardening | 处理用户输入、认证、外部集成 |
| debugging-and-error-recovery | 测试失败、构建出错 |
| performance-optimization | 性能瓶颈、Core Web Vitals |
| test-engineer (agent) | 测试策略、覆盖率分析 |
| browser-testing-with-devtools | 浏览器端调试 |

## 发布阶段
| Skill | 触发场景 |
|-------|---------|
| shipping-and-launch | 准备上线、灰度发布 |
| documentation-and-adrs | 记录架构决策 |
| deprecation-and-migration | 迁移旧系统 |

## 维护
| Skill | 触发场景 |
|-------|---------|
| code-simplification | 代码能跑但难读难维护 |
| git-workflow-and-versioning | 分支管理、冲突解决 |
| ci-cd-and-automation | CI/CD 流水线 |
