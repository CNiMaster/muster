# 复盘 0001：发布白名单外的改动静默丢失

**日期**：2026-08-18 发现并修复（commit a49ac6a）　**级别**：高危（用户数据丢失）　**状态**：已修复

## 事实

- 每个 runtime task 在独立 git worktree（分支 `muster/<projectId>/<taskId>`）执行；发布走文件级三方合并 + **产物白名单**（只合并 `result.artifacts` 声明的文件）。
- agent 在执行中顺手改了白名单外的文件（未在 artifacts 里声明）时，改动虽已 commit 进任务分支，但任务终态清理 worktree 时 `git branch -D` **强删分支**——白名单外的改动随分支消失，无留痕、无提示、无找回路径。
- 同类问题在后续"manual 合并/孤儿清理"实现中曾再次出现（修复轮已一并堵死），说明这是一个**模式级**缺口，不是一次性 bug。

## 根因

白名单是保护主干不被污染的安全机制，但它隐式定义了"白名单外 = 不发布"，而**没有人定义"白名单外 = 怎么处理"**。发布管线只对声明的文件负责，清理管线只对 worktree 生命周期负责，两者之间的"分支上还有未发布内容"状态成了三不管地带。

## 为什么自检没拦住

- 全量测试覆盖的是发布管线自身（声明什么发什么、冲突如何裁决），**"agent 漏声明"这个行为组合没有任何测试视角**——tsc、单测、集成、e2e 全绿。
- 静默丢失不产生任何错误信号，agent 自检（提交信息里的"全量过"）不可能看见。

## 补强了什么

- engine 清理 worktree 前：`diff base..branch + status` 减去 `publish_record.artifacts_json` 白名单，非空则**保留分支**不删 worktree，落 `task_event 'unpublished_changes_kept'` 留痕等用户处置。
- 修复轮进一步：所有新的合并/丢弃/清理路径（promoteTaskStaging、discard、孤儿清理）一律先做未合并内容检测，检测有内容未确认不清删。

**教训**：安全机制的白名单边界必须同时定义"边界外内容的处置语义"，否则白名单就是一个静默丢弃器；对"组合行为"（agent 漏声明 × 清理时机）要靠守护断言而不是靠测试用例枚举。
