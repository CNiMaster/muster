# 复盘 0003：蜂群记忆三连丢——汇总窗口截断、通用经验白写、专家 CRAFT 真丢

**日期**：2026-08-19 发现并修复（commit c99611d）　**级别**：中危（组织学习失效）　**状态**：已修复

## 事实

三个连环洞，各自独立又叠加成"蜂群跑得越多、丢得越多"：

1. **汇总窗口截断**：蜂成员汇报逐条写入汇总任务消息，但汇总任务装配上下文的 `recentDiscussion` 固定取最近 6 条——蜂数 >6 时早期汇报被窗口截掉，养蜂人带着不完整输入做收口。
2. **通用经验白写**：工蜂反思沉淀的 LESSON/RULE/PREFERENCE 写进工蜂的临时 profile 记忆区；群收口时临时工删除，`ON DELETE CASCADE` 连记忆行一起删掉——写的时候一切正常，召回时永远为空。
3. **专家 CRAFT 真丢**：专家蜂（穿戴人设）沉淀的方法论（CRAFT）同样挂临时 profile，同样被级联删——本应长存的组织方法论资产实际从未存活过一个蜂群周期。

## 根因

**记忆宿主与记忆生命周期错配**：临时工 profile 是"一次性"的，而沉淀出的经验/方法论应当比执行体活得久。写入侧与删除侧是两个组件，各自行为正确（写入成功✓/临时工清理✓），组合语义错误。窗口常量（6）则是在蜂群规模引入后没有重新审视的旧默认值。

## 为什么自检没拦住

每个组件的单测都绿：记忆写入测试✓、消息窗口测试✓、临时工删除测试✓。缺的是**跨组件生命周期链路测试**（写入→宿主删除→再召回），以及"窗口大小 × 蜂群规模"的边界断言。组件级正确性叠加不出系统级正确性。

## 补强了什么

- 汇总窗口按 `swarmSynthesis + beeCount` 扩窗（全保留 + 4 余量），蜂数不再受固定窗口截断。
- 工蜂通用经验不再单独沉淀（并入蜂群汇总，由根任务反思覆盖项目侧结论）。
- 专家 CRAFT 改挂**人设方法论档案宿主**（固定 id、`is_temp_only=1` 不入列表、无任职行永不删）；`dismissTempWorker` 删除 profile 前先 `preservePersonaCraftMemories` 迁移安全网（含候选态）。
- 召回侧 `loadContextMemories` 对 `persona_key` 非空按人设全局命中：方法论属人设不属于执行者，蜂与固定员工同池复用。

**教训**：一次性执行体产生的长寿命资产（经验/方法论）必须挂到**比它活得久的宿主**上；跨组件生命周期（写入→宿主消亡→召回）要有链路级测试，而不是各组件各自为政的单测。
