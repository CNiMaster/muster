# Agent 公司工作台分阶段实施清单

> 依据：[Muster Agent 公司工作台 PRD](./PRD-agent-company-workbench.md)

## 2026-07-05 本地 MVP 验收记录

当前已完成并验证“本地单用户长篇小说 Agent 公司”纵向闭环。详细阶段清单保留为完整产品范围，不把尚未实现的扩展项误标为完成。

验证证据：

- `npm run typecheck`：通过。
- `npm test`：19 个测试文件、123 项测试通过。
- `npm run build`：server 与 client 生产构建通过。
- `npm run test:e2e`：Chromium 5/5 通过。
- 真实 Claude Code 两轮冒烟通过：跨 Task worktree 复用同一 session，完成文件创建/更新、Artifact 登记和 Token/缓存统计。

本轮已交付的核心范围：

- 公司、部门、员工、项目、独立员工上下班、组织锁与第一负责人。
- 项目隔离线程、个人 Task 队列、@直联权限、依赖/追问/反馈和持续协调器。
- 项目镜像并行领取、监察建议、强制复盘、用户备注与显式继续。
- Git worktree 隔离写、原子发布、三方合并、冲突阻塞、回滚与成果预览。
- 小说公司默认岗位、初始化成果、章节维护事件、滚动规划和定时一致性任务。
- 组织/通信/工作流图、员工配置编辑、AI 设置向导与明确离线模板降级。
- Claude Code 模型设置、桥接测试、跨 worktree session 续接和结构化输出纠正。

明确留在后续范围：

- 员工级多 API 凭据与多模态执行器；当前为系统级 Claude Code 执行器。
- 自然语言修改组织图后的差异确认、部门级智能路由。
- 自动随机发起讨论、每日讨论预算和长时间 soak 测试；当前讨论由用户/Task 发起并有轮次、Token、时长及正式 Task 中断限制。
- 更多题材扩展包、PPT/Word/网页公司模板、多租户、积分和支付。

## 实施原则

- 每一阶段必须形成可运行、可验证的纵向闭环。
- 先建立状态和安全不变量，再接真实模型。
- 不在旧 Leader→Worker→Verifier 状态模型上继续叠加。
- 不迁移旧 `.muster` 测试任务数据。
- 所有并发与恢复能力先通过假执行器测试，再接 Claude Code。

## Phase 0：重构基线与安全网

### 目标

建立可测试的工程基线，明确可复用与废弃边界。

### 工作项

- [ ] 备份并清理旧 `.muster` 测试运行数据。
- [ ] 标记旧编排器、临时群聊和旧 Task 状态为待替换模块。
- [ ] 保留 Agent 进程启动、流式事件、沙盒、调度和备份能力。
- [ ] 建立正式测试命令、临时数据库和虚拟时钟。
- [ ] 建立执行器假实现，可模拟输出、追问、超时、失败和无进展。
- [ ] 拆分单文件前端入口，为新工作台建立模块化外壳。
- [ ] 定义统一错误码、事件 ID、幂等键和日志关联 ID。

### 验收

- [ ] 测试命令可以在干净环境稳定运行。
- [ ] 假执行器可以驱动一个最小 Task 完成。
- [ ] 旧数据删除不会影响源码和新数据库启动。

## Phase 1：公司、项目和员工基础模型

### 目标

用户可以创建公司、员工和项目，并正确执行上下班与项目隔离。

### 工作项

- [ ] 实现公司、部门、员工、项目和项目员工线程数据模型。
- [ ] 实现公司下班、上班、排空和强制复盘状态。
- [ ] 上班期间锁定正式组织配置。
- [ ] 实现项目独立 Task 命名空间。
- [ ] 实现跨项目只读引用。
- [ ] 实现公司第一负责人和项目第一负责人。
- [ ] 实现不可删除的运营监察基础角色。
- [ ] 实现公司与项目健康校验。
- [ ] 提供基础公司、员工和项目管理 API。

### 验收

- [ ] 同一员工可同时进入两个项目。
- [ ] 两个项目的上下文、Task 和文件引用不会串线。
- [ ] 上班时不能修改员工职责和组织关系。
- [ ] 项目可以只读引用另一项目成果，但不能写入来源项目。

## Phase 2：持久 Task 引擎

### 目标

以 Task 统一表达派发、队列、等待、反馈、追问、定时和恢复。

### 工作项

- [ ] 实现 Task 状态机和追加事件记录。
- [ ] 实现项目内序号与内部全局 ID。
- [ ] 实现父子、根、依赖和延伸关系。
- [ ] 实现原子领取、租约、心跳和过期恢复。
- [ ] 实现优先级、入队顺序和跳过未就绪任务。
- [ ] 实现结构化输入/输出协议。
- [ ] 实现 Task 内补充对话和最大追问轮次。
- [ ] 实现结果反馈后恢复原等待 Task。
- [ ] 实现安全暂停、检查点和终止。
- [ ] 实现事件触发和定时触发的统一入队接口。

### 验收

- [ ] 两个执行线程不能领取同一个 Task。
- [ ] 接收者追问后，派发者补充资料可恢复原 Task。
- [ ] 依赖未完成时不会误执行，但不阻塞其他可运行 Task。
- [ ] 进程异常后租约过期，Task 可安全恢复且不会重复提交。

## Phase 3：执行器、上下文与用量

### 目标

在不绑定员工身份的前提下接入本地 Claude Code，并记录真实运行成本。

### 工作项

- [ ] 定义执行器适配接口。
- [ ] 将现有 Claude Code 进程能力封装为首个适配器。
- [ ] 实现员工执行器配置和用户级凭据引用。
- [ ] 限制 Claude Code 默认只能访问当前项目和授权参考项目。
- [ ] 实现项目级上下文组装和引用记录。
- [ ] 实现模型会话复用、压缩和轮换策略。
- [ ] 实现公司、项目、员工、Task 和模型级 Token 统计。
- [ ] 实现可选预算软限制。
- [ ] 实现单次运行绝对安全限制和无进展检测。

### 验收

- [ ] 员工切换执行器不改变其公司身份和项目 Task。
- [ ] 不同项目不会复用彼此业务上下文。
- [ ] Token、缓存和工具调用可准确归集。
- [ ] 无进展 Task 被保存并终止，不会无限运行。

## Phase 4：组织、通信与流程图编辑器

### 目标

用户可以通过图形界面创建和修改 Agent 公司。

### 工作项

- [ ] 实现统一节点/边画布基础设施。
- [ ] 实现组织图编辑。
- [ ] 实现通信权限图编辑。
- [ ] 实现工作流图编辑。
- [ ] 实现拖动、连线、属性面板和删除/归档操作。
- [ ] 实现自然语言修改后的图差异预览。
- [ ] 实现上班只读、下班可编辑。
- [ ] 实现断裂流程、非法通信、缺失责任岗位和不可达节点校验。
- [ ] 实现部门与员工状态看板。

### 验收

- [ ] 用户可以不编辑配置文件完成公司结构调整。
- [ ] 非法关系无法保存，并提供明确原因。
- [ ] 三种图共享交互体验但不会混淆语义。
- [ ] 图编辑后重新上班，项目线程使用新配置。

## Phase 5：项目镜像、监察与持续运行

### 目标

项目能够持续运转、临时扩容并可靠处理异常。

### 工作项

- [ ] 实现项目级员工镜像。
- [ ] 镜像共享根员工 Task 池并独立领取。
- [ ] 镜像结果和成本聚合到根员工。
- [ ] 实现镜像排空和项目结束自动释放。
- [ ] 实现监察员状态、拥堵、缺席、心跳和循环检查。
- [ ] 实现项目优化建议，不允许自动扩容。
- [ ] 实现普通非阻塞进度汇报。
- [ ] 实现按 Task 数、时间或里程碑触发强制复盘。
- [ ] 实现按根员工汇总的轮次看板。
- [ ] 实现用户摘要编号备注和“继续工作”按钮。

### 验收

- [ ] 新增镜像后积压 Task 可以并行完成且不重复。
- [ ] 减少镜像不会丢失当前 Task。
- [ ] 达到复盘点后不再领取新 Task。
- [ ] 用户未点击继续前项目不会自行恢复。
- [ ] 监察建议不会直接改变项目容量或方向。

## Phase 6：安全成果工作区

### 目标

所有成果可追踪，并保证并发写入不会静默覆盖。

### 工作项

- [ ] 实现成果注册表和成果处理器接口。
- [ ] 实现 Task 隔离写层和共享只读视图。
- [ ] 实现文本三方合并。
- [ ] 实现重叠冲突检测和阻塞。
- [ ] 实现二进制资源独占锁。
- [ ] 实现发布前快照和回滚。
- [ ] 实现成果责任岗位和修改权限。
- [ ] 实现权威成果、管理成果和派生只读视图。
- [ ] 实现 Markdown/纯文本编辑器。
- [ ] 实现图片与 PDF 预览及外部应用打开。

### 验收

- [ ] 并行修改同一文本的不同区域可安全合并。
- [ ] 重叠修改不会覆盖任一方成果。
- [ ] 二进制文件无法被两个 Task 同时写入。
- [ ] 任意正式提交都可定位来源 Task 并回滚。

### 目标

### 工作项

- [ ] 实现长篇小说公司创建 Skill。
- [ ] 实现题材扩展包和默认岗位推荐。
- [ ] 强制分离项目第一负责人和主写手。
- [ ] 实现人物、情节和监察基础岗位。
- [ ] 实现可选世界观、时间线、伏笔、连续性和文风岗位。
- [ ] 实现对话式项目初始化和结构化小说设定册。
- [ ] 实现参考样文与风格档案。
- [ ] 实现计划大纲编辑器。
- [ ] 实现实际剧情进度视图。
- [ ] 实现只读人物关系图。
- [ ] 实现章节编辑器。
- [ ] 实现章节完成后的变更摘要协议。
- [ ] 实现人物、情节、时间线和伏笔维护事件 Task。
- [ ] 实现小说项目滚动规划和阶段复盘。

### 验收

- [ ] 用户可以从一句想法创建小说公司和项目。
- [ ] 用户确认初始 Task 后，第一负责人开始当前阶段规划。
- [ ] 主写手需要新人物时能向人物设计派发完整工作包。
- [ ] 信息不足时双方在原 Task 中补充并恢复。
- [ ] 章节完成后项目资料和派生视图得到更新。
- [ ] 达到复盘点后用户可查看员工级成果摘要并纠正方向。

## Phase 8：受限讨论与体验完善

### 目标

增加可控的创意协作，并完成本地 MVP 体验。

### 工作项

- [ ] 实现受 Task 约束的临时讨论。
- [ ] 实现空闲员工选择、随机轮次和每日成本限制。
- [ ] 正式 Task 到达时让参与者安全退出讨论。
- [ ] 实现讨论结论汇总和建议 Task。
- [ ] 确保建议不能自动执行。
- [ ] 完善公司、项目和 Task 对话界面。
- [ ] 完善关键事件摘要与完整讨论展开。
- [ ] 完善首次使用引导、空状态和错误恢复。
- [ ] 完成端到端浏览器测试和长时间运行测试。

### 验收

- [ ] 讨论不会无限运行或抢占正式工作。
- [ ] 讨论结论可追踪，但不会自动修改项目。
- [ ] 本地应用重启后公司、项目、Task 和检查点完整恢复。
- [ ] 长篇小说端到端验收场景连续运行通过。
