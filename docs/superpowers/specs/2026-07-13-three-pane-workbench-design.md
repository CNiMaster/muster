# Muster C3 安静工作台设计规格

> ⚠️ 历史注记（2026-08-16）：公司页章节已被公司退场取代；三栏骨架由 2026-08-13 改版 + WorkbenchShell 继承（现仅项目页）。

日期：2026-07-13

## 目标

把公司页和项目页重组为接近 Codex 使用习惯的三栏工作台，同时避免把 Muster 的大量功能、菜单和设置一次性暴露给用户。

设计只要求用户理解三个动作：

1. 在左栏选择工作。
2. 在中栏完成工作。
3. 在右栏查看与当前工作相关的现场信息。

首页、公司创建向导、员工库、执行器、权限和设置页面继续使用单栏或普通管理布局，不强行套入三栏。

## 设计原则

### 单一导航方向

- 全局只保留顶部一条横向工具栏。
- 左栏内部只使用纵向列表。
- 中栏和右栏不再分别拥有独立页签栏、横向导航或二级工具条。
- 高级命令通过 `⌘ K` 命令入口或内容区的省略菜单提供，不长期占用界面。

### 渐进展示

- 默认只显示当前工作需要的信息。
- 员工会话、上下文体积、执行器诊断等信息进入右栏摘要，需要时再展开。
- 工作流设计、复盘预算、线程扩容等高级功能从主流程移入“更多”菜单或专用页面。
- 没有审批、风险或运行异常时，右栏不展示空白告警模块。

### 系统自动安排

- 用户不需要决定一个模块应放在哪一栏。
- 点击任务、对话、群聊或看板后，中栏直接切换到对应工作界面。
- 右栏根据中栏当前对象自动变化。
- 第一版不提供任意拖拽、跨栏移动或每栏独立页签，避免引入新的学习成本。

## 工作台结构

```text
┌──────────────────────────────────────────────────────────────┐
│ Muster  [左栏]  公司 / 项目 / 当前工作   ⌘K  [右栏]  主操作 │
├──────────────┬─────────────────────────────┬─────────────────┤
│ 左栏         │ 中栏                        │ 右栏            │
│ 选择工作     │ 完成当前工作                │ 查看当前现场    │
│              │                             │                 │
│ 项目任务     │ 任务 / 对话 / 群聊          │ 参与员工        │
│ 最近对话     │ 员工看板 / 工作流 / 成果    │ 运行与会话      │
│ 待审批       │                             │ 审批与风险      │
│ 员工看板     │                             │ 快捷决定        │
└──────────────┴─────────────────────────────┴─────────────────┘
```

### 顶部工具栏

顶部工具栏是唯一的横向控制区，包含：

- Muster 标识。
- 左栏开关。
- 公司、项目和当前对象面包屑。
- `⌘ K` 搜索与跳转入口。
- 右栏开关。
- 当前页面唯一主操作，例如“发布工作”或“新建项目任务”。

顶部不再平铺首页、员工库、执行器、权限和设置等全部入口。这些入口放入 Muster 标识菜单或命令入口，减少视觉噪音。

### 左栏：选择工作

左栏是当前公司或项目的统一工作列表，不再是多套菜单的集合。

默认分组：

- 正在进行：活跃项目任务及其简短进度。
- 沟通：相关群聊、最近单聊和未读数量。
- 需要处理：待审批、失败运行和需要补充信息的工作。
- 固定入口：员工看板、项目文件和更多功能。

点击任一项目后，中栏切换内容并更新 URL。浏览器前进和后退可以恢复之前的工作，不额外实现页签系统。

左栏收起后保留一个窄把手，点击即可恢复。收起状态和宽度保存在本机，并按用户工作区记忆。

### 中栏：完成工作

中栏始终只显示一个主要工作界面：

- 项目任务：目标、进度、任务对话、工作单和成果。
- 单聊或群聊：消息记录和输入区。
- 员工看板：公司员工状态与当前工作。
- 工作流：可视化工作流画布。
- 成果：文件或结构化成果预览。

中栏顶部只展示当前对象标题、状态和一个省略菜单。省略菜单包含归档、完成、打开专用页面等低频操作。

页面级主操作放在全局顶部工具栏；内容区不重复出现同义按钮。

### 右栏：查看现场

右栏是自动跟随中栏的上下文检查器，不是第三套导航。

映射规则：

| 中栏内容 | 右栏内容 |
| --- | --- |
| 项目任务 | 参与员工、运行状态、会话健康、审批和成果摘要 |
| 单聊 | 员工身份、当前任职、执行器和最近工作 |
| 群聊 | 群成员、关联任务、等待回复和共享成果 |
| 员工看板 | 当前选中员工的详细状态和快捷操作 |
| 工作流 | 当前节点负责人、运行条件和校验问题 |
| 成果 | 来源工作单、负责人、版本和发布状态 |

右栏没有内容时显示精简的项目现场摘要，而不是大量空卡片。出现待审批或高风险事件时可以自动展开，但不能改变用户当前的中栏内容。

右栏收起后保留一个窄把手和待处理数量。收起状态和宽度保存在本机。

## 页面与状态映射

### 公司页

- 默认中栏显示公司概览。
- 左栏列出项目、公司级沟通、待处理事项和员工看板。
- 右栏显示公司运行状态、岗位缺口和待审批摘要。
- 原有“概览、团队、项目、活动、设置”横向标签移除，转换为左栏入口或专用页面。

### 项目页

- 默认中栏打开最近访问的项目任务；没有项目任务时显示创建任务引导。
- 左栏列出项目任务、群聊、待处理事项、员工看板和项目文件。
- 右栏根据当前项目任务或对话自动展示现场。
- 项目任务、员工工作单和成果继续保持现有数据边界，不因为界面调整而改变会话模型。

### 单栏页面

以下页面保持普通布局：

- 首页。
- 公司创建向导。
- 员工库与员工基础档案编辑。
- 执行器中心。
- 权限中心。
- 全局设置。

从工作台进入这些页面时保留返回当前公司或项目的入口。

## 首次使用引导

首次进入工作台时展示一次不超过三步的聚焦动画：

1. 左栏高亮，标签为“选择工作”。
2. 中栏高亮，标签为“完成工作”。
3. 右栏高亮，标签为“查看现场”。

每步只使用一个短句和“下一步”按钮。用户可以跳过；完成或跳过后不再自动弹出，可从帮助菜单重新播放。

空状态使用图形、示例和一个主按钮，不使用长篇说明。

## 响应式行为

- 宽度不少于 1180px：显示完整三栏。
- 宽度 820px 至 1179px：默认收起右栏，需要时作为覆盖层打开。
- 宽度小于 820px：默认只显示中栏；左栏和右栏通过顶部按钮作为抽屉打开。
- 抽屉打开时提供遮罩和清晰关闭按钮，并支持 Escape 关闭。
- 中栏设置合理最小宽度，不能为了保留侧栏而产生横向滚动。

## 交互与可访问性

- 左右栏开关使用可读的 `aria-label` 和 `aria-expanded`。
- 键盘快捷键：`⌘/Ctrl + B` 开关左栏，`⌘/Ctrl + Shift + B` 开关右栏，`⌘/Ctrl + K` 打开命令入口。
- 所有快捷键都有按钮入口，快捷键不是完成任务的必要条件。
- 当前左栏项目使用文字、背景和边框共同表示，不能只依赖颜色。
- 动画遵循 `prefers-reduced-motion`。
- 焦点在抽屉打开时被约束在抽屉内，关闭后返回触发按钮。

## 前端架构

新增清晰的布局边界，避免继续扩大 `CompanyPage.tsx` 和 `ProjectPage.tsx`：

- `WorkbenchShell`：负责三栏、宽度、收起状态、响应式和快捷键。
- `WorkbenchHeader`：负责面包屑、栏位开关、命令入口和唯一主操作。
- `WorkNavigation`：负责左栏统一列表。
- `WorkSurface`：根据路由渲染中栏当前工作界面。
- `ContextInspector`：根据当前对象渲染右栏上下文。
- `WorkbenchGuide`：负责首次三步引导。
- `useWorkbenchPreferences`：负责本机布局偏好存储和恢复。
- `workbench-routes`：把现有公司、项目、项目任务、对话和看板路由映射为工作台对象。

`WorkbenchShell` 只处理布局，不直接请求业务数据。公司和项目适配层负责把现有查询结果转换为左栏与右栏需要的视图模型。

## 数据与路由

- 当前中栏对象必须体现在 URL 中，刷新后可以恢复。
- 原有项目任务查询参数迁移到明确的工作台路径或保持兼容跳转。
- 左右栏开关和宽度只保存在 `localStorage`，不写入数据库。
- 当前工作、公司和项目仍由服务器数据决定，不能只存在前端状态。
- WebSocket 更新继续驱动任务、审批、运行和员工状态刷新。

## 错误与恢复

- 左栏数据失败时，中栏仍可显示当前路由内容，并在左栏提供重试。
- 右栏数据失败时只影响现场摘要，不阻断中栏工作。
- 当前对象已删除或归档时，中栏展示明确状态，并推荐返回最近活跃任务。
- 存储的栏宽或开关状态无效时恢复默认值，不导致页面空白。
- 新工作台组件继续使用页面级错误边界，单栏崩溃不能拖垮整个应用。

## 测试与验收

### 单元测试

- 栏位偏好读取、写入和无效值恢复。
- 中栏对象到右栏上下文的映射。
- 公司和项目数据到左栏分组的映射。
- 响应式布局状态决策。

### 组件测试

- 左右栏独立开关。
- 键盘快捷键。
- 中栏切换后右栏自动更新。
- 引导的下一步、跳过和重新播放。
- 待审批数量在右栏收起时仍可见。

### E2E

- 公司页和项目页进入三栏工作台。
- 任务、群聊、员工看板切换时 URL 和中栏同步。
- 浏览器前进、后退和刷新恢复当前工作。
- 桌面三栏、平板右栏覆盖层和手机双抽屉均无横向溢出。
- 审批出现时右栏提示更新，但中栏当前工作不被替换。
- 首页、向导和设置页面保持单栏。

## 本阶段不做

- 任意拖放面板。
- 每栏独立页签系统。
- 跨栏移动内容。
- 用户自定义任意布局模板。
- 多窗口同步布局。
- 修改项目任务、员工工作单或 CLI 会话的数据模型。

这些能力只有在真实使用证明有必要时再单独设计。
