# 批次 H8：停止语义 + 即时回执 + 环境预检

状态：implementing（2026-08-22 与用户多轮定稿；2026-08-23 实施中第四、五轮收敛见下）
来源：批次 H 评审 I5（插话双跑）+ 用户三轮设计收敛（单停止/安全规则/按钮菜单/打断记录/批量暂停）+ 用户新增两条观察（即时回执感、环境预检入程序）。

## 第四、五轮收敛（2026-08-23 实施中用户定稿，覆盖下方按钮形态）

- **第四轮**：主按钮由「停止」改「暂停」（安全停语义）；「立即停止」（不等边界急救，如误跑 rm）收进 ⌄ 菜单。
- **第五轮（终稿）**：**去掉针对单个 agent 的停止入口**——四种停止（暂停/急停 × 负责人/全局）太多，减少用户判断负担。终稿：
  - 主按钮 `⏸ 暂停 ⌄` ＝ **全局暂停**（本项目全部 running/claimed 任务各自等安全边界；queued/waiting 不动——没有执行器在跑）
  - ⌄ 菜单单项 ＝ `⚠ 立即停止本项目全部任务`（急救，不等命令跑完，各任务照样落打断记录）
  - 等待窗口 ＝ `⏸ 暂停中…` 禁用；停完用户发命令即可恢复全局工作
  - 工作现场面板头部第二入口：`⏸ 全部暂停` + `⚠ 急停`（同语义）
- **点名流（用户描述，薄版落地）**：运行中不提供单点停；停之后在执行者目录对出错执行者点名（⋯ 菜单）——`撤销他的改动`（discard-stop，回基线重跑）｜`点名上级审查`（自动组装消息发给其 dispatcher/负责人，附停点与文件清单，走组织链修正，用户不下场改）。
- **插话/排队 ↑立即**：同全局语义——stop-all 安全停 + 立即送出。
- **第六轮（纠错命名与治理链）**：点名入口改名「**纠错**」；**不提供用户直发撤销**（用户对全局不了解，撤否由组织判断）。流程=先安全停该执行者（流程内单点停）→ 用户描述问题 → 发给上级链处置（重新安排/重做/修改工作/评估撤销；提示「对其他执行者有影响请一并调整」——影响面扩大判断也是 agent 的活）。
- **第七轮（上级自动路由）**：纠错收令人=**被纠错执行人的上级**，不都给人事——中央岗（人事/养蜂人等系统岗）→ 第一负责人；有派遣人 → 派遣他的领导（蜂→养蜂人/被派专家→负责人自然成链）；负责人本人被纠错 → 人事（重新安排）；兜底 → 第一负责人。收令人不开放用户直联时回落负责人。
- **已知问题（后续批次）**：~~立即停止杀 CLI 进程后孙进程孤儿~~ **第九轮已修**：claude 适配器 spawn 改 `detached:true` 自成进程组，SIGINT/SIGTERM/SIGKILL 全走组信号 `kill(-pgid)`——急停连 bash 工具孙进程一锅端（终端 Ctrl+C 的前台进程组语义）；进程组止损有原语单测兜底。
- **第九轮（急停接续保真，用户两问收敛）**：用户指出「杀进程会导致后面任务接不上」+「SIGINT 等 5s 对急停无意义（杀不到孙进程）」。核实与定稿：
  1. **接续断点真存在**：适配器 close 非 0 退出走 reject 丢 session id；且安全停三汇入点在 session 持久化（runTask 正常流程 815 行）之前 return，跳过落库——「继续」时 --resume 无从谈起。修复：close 非 0 时已有 resultSessionId 则 resolve 部分结果带回（SIGTERM 杀掉也保得住，CLI session 文件流式落盘）；停止检查点先持久化 `_sessionIdHint` 再 finalize。
  2. **急停回退直接强停**：SIGINT 阶梯（SIGINT+5s→SIGTERM）废弃——两种单进程信号都够不着孙进程，等 5s 纯放跑 rm；急停=forceAbort 立即执行（event `stop_forced` reason=user-immediate），接续保真由上面两点承担，孙进程止损由进程组隔离承担。
  3. **暂停（SIGINT）语义澄清**：对 CLI，SIGINT=打断当前命令收尾（Ctrl+C 语义），不是「等命令跑完」——等边界仅 API 执行器（tool-loop）可精确做到；CLI 的组信号 SIGINT 顺带打断其工具子进程。fake-executor 对齐该语义（stopSignal 打断 delay 返回带 session 的 blocked 结果）。
- **已知问题（非本批，main 同样复现）**：smoke-2 产物内容两例（GET content 403 路径不在允许的根目录内 / PUT 连锁 undefined）在 main@4dc7398 同挂，上一会话同机曾全绿——疑环境/路径漂移（isPathAllowed 解析口径），留专项排查；H8 与 main 行为一致。
- 单任务 `/stop` 端点保留（TaskDetailPage 暂停按钮、pause rewire 等单任务语境用）；`/interrupt` 保留为强停原语（引擎关机同款），UI 不再调用。

## 用户定稿设计

### 1. 停止=单动作，内部按执行状态自动分级（安全规则）

| 当前在干什么 | 停止动作 |
|---|---|
| 正在写/编辑文件 | 等这次写完（整文件原子写，到边界即停） |
| 正在跑 Bash 命令 | 等命令结束再停（中断 git/npm 可恢复但烦人；worktree 隔离兜底） |
| 正在等模型响应 | 直接停 |

- **超时兜底**（默认 60s，设置可调）：等待边界有上限，防 watch/长命令把停止挂死；到点自动强停（SIGTERM），半成品走保留分支+文件清单，**同样落打断记录**。
- 实现要点：请求停止标志（task 行 stop_requested）→ 引擎在工具调用边界检查（API tool-loop 每轮工具后天然可查；CLI 在 onToolCall/onOutput 回调边界查+SIGINT 优雅打断让模型收尾总结=停点摘要）。
- **I5 收敛**：停止后 state='paused'（不是回 queued 让位重跑）——打断不是重跑；插话模式同语义改造。
- pauseTask 既有缺陷顺带修复：现在只改状态不通知引擎（运行中"暂停"实际停不下来），统一并入本套安全停逻辑。

### 2. 按钮三态合一（评审 spec 偏差③消解）+ 侧边菜单

```
[输入框空 + 任务运行中]  [ ■ 停止 ⌄ ]   ← 单击=停当前任务；⌄ 菜单=「暂停本项目全部任务（N 个运行中）」
[输入框有字]             [ 发送 ↑ ]     ← 发送后进排队通道，按钮回停止态
[任务空闲]               [ 发送 ↑ ]
[已点击停止，等边界]      [ ⏸ 停止中… ]  ← 禁用态防连击；内部超时自动兜底，无需二次操作
```

- 批量暂停第二入口：工作现场面板执行者目录顶部「全部暂停」；逐任务走同一安全停。
- 不经负责人 agent 转发暂停（控制面确定性操作直做）；全部停下后**可选**自动派汇总任务给第一负责人（"各任务停点清单，请建议下一步"——分析活才给 agent）。

### 3. 打断记录卡（停后出现在消息流/任务详情）

- 停点：停在第几步、最后动作、模型收尾总结一句
- 已改文件清单（含未完成标注）
- 三出口：**继续**（从保留 worktree 现状续跑，不从头来）｜**补齐**（发新任务给同一员工，自动附打断记录）｜**回退**（丢弃这批改动重来）
- 工程要点：停止时 worktree 保留（现有 unpublished_changes_kept 机制升级为面向用户的记录卡）；"继续"要求引擎复用 task_runtime 而非重建（现状会从基线重来——需改）。

### 4. 即时回执（用户新增观察：操作后必须立刻"被回应"）

- 用户点 停止/暂停/↑立即 的**那一刻**，对话区立刻出系统回执消息：
  - 受理：「已请求停止——等待当前命令（Bash: npm test）完成后停下」（带当前动作名）
  - 生效：「已停止：完成 2/5 项，改了 2 个文件」+ 打断记录卡
- 生效的可验证性（用户"后台停没停我不清楚"的解法）：任务状态徽章可见变「已暂停」+ LiveProcessBar 消失 + trace 停止滚动——三条线索交叉确认。
- 排队条 flush 同理：立即回执「已打断并送出」。

### 5. 环境预检（用户新增：经验入程序）

- **产品侧**：执行器 spawn 失败的错误分类识别安全拦截特征（EPERM/Gatekeeper 报错串），对话区给可操作提示（去 隐私与安全性 允许 / 对二进制去隔离属性），不裸报错。
- **工程侧**：`npm run preflight`——测试/冒烟前探测 node/git/esbuild spawn 正常 + 检测隔离属性（xattr -l），发现即提示"请先完成系统授权再跑测试"，把安全弹窗从测试中途随机炸变为开跑前一次性处理。playwright webServer 命令前置调用。

## 实施边界

- 迁移：task 表加 stop_requested 列（官方时间戳命名）。

- H5 的 interruptTask 保留为"强停"原语；新 requestStopTask 为"安全停"入口；插话模式改为安全停+paused 语义。
- 测试：安全停边界（写文件中/Bash 中/模型等待中三态各一例）、超时升级、打断记录三出口、按钮三态、批量暂停、预检脚本。
