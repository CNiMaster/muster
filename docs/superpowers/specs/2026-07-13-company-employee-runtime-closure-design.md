# 公司、员工与运行闭环深度打磨设计

## 目标

让 Muster 从“功能很多的管理页”变成普通用户可以顺着完成工作的多 Agent 公司工作台，同时补齐代码层可验证的 CLI 运行、审批、会话恢复与实时反馈闭环。

## 产品结构

公司页调整为驾驶舱，按“概览、团队、项目、活动、设置”组织信息。概览只展示公司健康、待处理事项、运行中项目和唯一推荐行动；团队承载部门、员工与招募；项目承载项目入口；活动承载对话、事件与协作；设置承载章程和组织图等低频能力。

员工采用三层心智：全局员工档案描述稳定身份与基础能力，公司任职描述岗位、部门、执行器、权限和通信边界，项目活动描述当前线程、会话健康与成果。员工创建统一为“新建档案、从员工库招募、从岗位模板招募”三种来源，避免页面同时出现互不解释的入口。

公司创建向导不再以小说为产品入口。第一步选择公司模板或通用公司类型，第二步确认团队，第三步检查执行器准备情况，第四步创建首个项目。长篇小说保留为内置模板。

## 运行闭环

增加统一 RunWatchdog，覆盖启动、无输出、总运行时间、连续网络错误、无结果退出和审批等待超时。所有执行器通过同一生命周期上报开始、活动和结束；失败必须分类并进入有限恢复链，禁止隐藏等待。

CLI 代码级契约测试覆盖默认模型不指定、显式会话恢复参数、Codex RPC 审批与 compact、Claude 两类 Hook、Antigravity 临时插件、失败关闭和临时文件清理。真实 CLI 冒烟不是本轮要求，因为用户明确要求代码层检查。

实时事件为项目任务创建、完成、归档、工作单状态、审批等待/决定和线程压缩/换代提供统一事件。前端收到事件后精确失效公司驾驶舱、员工任职、项目任务、审批和线程查询。

## 可用性原则

- 每个页面首屏只有一个主要动作。
- 专有名词首次出现时提供一句解释。
- 执行器不可用时显示原因和可操作修复入口。
- 危险操作使用确认对话并说明影响范围。
- 公司在线时不允许静默改变正式组织配置。
- 归档项目任务只读；新项目任务不复用旧会话。

## 代码边界

- `CompanyPage` 拆为驾驶舱容器和五个专用分区组件。
- 员工招募表单抽为复用向导，Company 页面只负责公司任职。
- 员工档案页显示身份与能力；任职卡显示执行器和权限健康。
- Watchdog 与 SessionManager 分离：前者管理进程时间和活动，后者管理上下文容量与会话换代。
- 所有新增行为先写失败测试，再实现最小代码。

## 验收

代码级验证覆盖公司驾驶舱派生状态、统一招募、员工三层 DTO、执行器健康、Watchdog、审批桥、会话恢复、实时缓存失效和文档一致性。最终执行 `npm test`、`npm run typecheck`、`npm run build`、`npm run test:e2e` 与 `git diff --check`。
