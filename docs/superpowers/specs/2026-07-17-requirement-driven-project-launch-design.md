# 需求驱动的项目启动与能力发现

> 日期：2026-07-17  
> 状态：第一阶段已实现（任务启动门与可验证能力快照）

## 真实缺口

现有能力中心、公司蓝图和 Task 级 Skill 解析已经能描述「某岗位推荐什么」，但不能回答一次具体制作是否真的可做：新项目会直接自动派发首个 Task，项目任务也能直接派工。结果是用户尚未确认效果、视觉参考、资料和限制，公共 `tools/` 目录又容易被误解为已安装且通用的能力。

## 用户路径

`项目 / 项目任务 → 需求澄清 → 能力发现 →（需要时）视觉参考或设计稿确认 → 明确允许制作 → 员工工作单`

1. 用户描述预期效果、受众、风格/表现手法、约束、交付物、外部资料需求和已有参考。
2. 用户可以声明需要核验的 capability / Skill。系统读取公司能力绑定、启用工具、固定执行器及其最近连接状态、本地可加载 Skills，生成一次带时间戳的发现快照。
3. 发现结果把「已配置路径」「仅候选、待补齐」「未找到」分开显示。候选工具不等于安装、授权或唯一方案；员工可使用自己已有的等效能力。
4. 用户标记需要视觉确认时，必须记录至少一个已确认视觉参考或设计稿，才可解锁制作。
5. 用户确认后，才可派发员工工作单；服务端同样阻止绕过 UI 的未确认 Task 创建。

## 数据与执行边界

`project_task` 新增 `launch_state`、`launch_brief_json`、`capability_discovery_json`、`launch_confirmed_at`。历史项目任务迁移为 `confirmed`，不改变既有运行。

- `launch_brief_json` 是用户确认的需求前提，而不是模型推测。
- `capability_discovery_json` 是可审阅快照，基于实际固定执行器 / 连接探针、`capability_binding`、公司启用工具和本地 `skills/*/SKILL.md`。
- 外部资料需求只作为待收集项保存；本阶段不伪造网络检索成功。员工可在确认后按权限与连接器能力补充资料。
- 对能力目录只做软诊断，不做强制安装或强制工具选择。

## 后续演进

- 将员工的研究/视觉探索作为显式的「启动准备」Task，产出可审核资料包，而非直接进制作。
- 接入实际连接器能力探测与外部资料检索时，将来源、许可、时间与摘要写入项目素材区；未验证来源继续显示为待确认。
- 将视觉参考扩展为素材区对象和设计评审版本，而不仅是链接/路径说明。
