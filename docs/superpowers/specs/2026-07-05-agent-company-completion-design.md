# Muster Agent 公司工作台完成设计

## 目标

在保留现有 React、Express、SQLite、Claude Code 和 Git worktree 基础设施的前提下，把当前“功能模块已存在但运行链未接通”的实现改造成可以持续工作的本地单用户 Agent 公司。首个完整垂直场景是长篇小说公司。

完成后的系统必须满足：

- 公司上班后，项目员工线程可以持续领取各自 Task。
- Task 只能由指定员工及其镜像领取。
- Agent 可以在一个 Task 内追问、派发依赖、等待反馈并恢复。
- 所有 Agent 文件修改必须通过隔离 worktree 发布；隔离或发布失败时阻塞，禁止降级直接写正式目录。
- 用户能在公司或项目对话中看到第一负责人的实际回复和关键事件。
- 工作流、通信权限、复盘阈值、定时任务、用量统计和小说事件进入真实运行链。
- 所有自动行为可追踪、可恢复，并通过 SQLite 与 Git 保持一致。

## 方案选择

采用“保留外壳、重构运行内核”方案。

不再次重写整个项目，因为现有数据库、页面、执行器、worktree 和大部分领域对象可复用；也不只修表面 P0，因为未接线的自动规划、用量、复盘和小说事件会继续造成假完成。

## 架构

### 1. Project Runtime Coordinator

新增项目运行协调层，成为持续运行的唯一入口，负责：

1. 公司上班时为活跃项目建立缺失的 primary thread。
2. 恢复过期租约。
3. 到达复盘阈值时进入安全暂停。
4. 无正式 Task 时给第一负责人创建一次规划 Task。
5. 有正式 Task 时结束或取消尚未执行的讨论 Task。
6. 按线程和镜像并发上限调用 TaskEngine。

HTTP 手动 pump 和后台轮询必须调用相同协调层，避免两套行为。

### 2. Task 领取不变量

领取查询必须同时满足：

- Task 与线程属于同一个项目。
- Task 已指定员工时，员工必须等于线程的 `agent_id`。
- 未指定员工的 Task 只能按明确的路由规则认领；首版由项目第一负责人认领，不允许任意员工抢占。
- 镜像与 primary 共享同一员工 Task 池，但原子领取保证不重复。
- 依赖均完成。

领取不得改写原 Task 的负责人，只写 `assignee_thread_id` 和租约。

### 3. 执行与成果发布事务边界

Task 执行分成：

`claimed → running → execution_result_pending → published/completed`

首版不新增公开状态值，而在引擎内部延迟 `completeTask()`：

- `completed` 结果必须先发布成果并登记 Artifact，全部成功后再标记 Task 完成。
- 冲突、缺少声明文件、路径错误或 Git 失败均把 Task 标记为 `blocked`。
- worktree 创建失败直接阻塞 Task。
- `waiting_input` 和 `waiting_dependency` 的文件变化先提交到 Task 专用分支并保留可恢复引用，不能删除后丢失。
- 没有文件变化的等待 Task 可以清理 worktree，并依靠持久 Claude session 与 Task 消息恢复。

发布记录保存 base commit、Task commit、正式 commit、冲突和状态。禁止使用 `reset --hard` 作为回滚后备。

### 4. 上下文与跨项目引用

上下文装配器按工作包显式加载：

- 公司章程。
- 项目说明和设置。
- 员工职责、技能、工具、通信权限。
- 当前 Task、父 Task 摘要、最近 Task 消息。
- `contextRefs` 指向的当前项目 Artifact。
- 已授权 `project_reference` 中的文件，只读加载。

文件内容设置单项与总量上限，超限时提供摘要和路径清单，不能静默遗漏。

### 5. 完成后副作用

引擎成功完成 Task 后统一执行：

- 记录真实模型、Token、缓存、工具调用、耗时和费用。
- 登记或更新 Agent 声明的 Artifact。
- 若 Task 来自用户对话，向原公司或项目对话写入第一负责人回复。
- 若完成章节成果，派发人物、情节等维护 Task。
- 发布 WebSocket 事件。
- 检查复盘阈值。

副作用必须幂等，使用 Task ID 和事件类型建立唯一键或先查后写。

### 6. 工作流与通信

通信权限以 `agent_definition.contact_allow_json` 为运行权威源，通信图是其可视化编辑器。用户在通信图连线或删除时，同一事务同步权限，避免“图存在但派发被拒绝”。

工作流节点属性必须包含责任员工或角色、Task 协议模板和后续边条件。协调层只自动推进明确配置的工作流，不让模型自行解释图语义。没有工作流的项目继续使用第一负责人动态规划。

### 7. 公司、项目、员工和镜像生命周期

- 公司上班前运行健康检查，并为项目建立线程。
- 下班进入 `draining`，停止领取新 Task；运行中的 Task 完成或保存检查点后转 `off`。
- 项目第一负责人为空时继承公司第一负责人并持久化。
- 项目员工由项目线程明确表示；小说项目默认加入公司基础岗位。
- 运营监察不可删除，只能下班后修改。
- 镜像可在线增加；删除前必须确认没有运行或已领取 Task。
- 线程状态由引擎真实维护，不再永久显示 `idle`。

### 8. 长篇小说闭环

小说项目创建时生成结构化设置和基础 Artifact：

- 项目说明、故事梗概、文风档案、计划大纲。
- 人物档案、世界观、时间线、伏笔资料。
- 人物关系、实际剧情、实际时间线只读视图。

章节发布成功自动产生 `chapter_completed` 事件，由人物、情节及可选岗位维护资料。只读视图由对应维护 Task 生成，用户不能直接修改。

创建公司、员工和项目向导首版调用真实 Claude Code 生成结构化建议；执行器不可用时明确显示离线模板，不伪装成 AI 结果。

## 错误处理

- 不安全降级一律禁止。
- 可恢复错误进入 `failed` 并允许人工重试。
- 需要用户或依赖输入进入对应等待状态。
- 文件冲突、预算、无进展和违反权限进入 `blocked`。
- 每个错误写 Task Event、结构化日志和实时事件。
- 后台轮询单次失败不能停止整个公司，但相同错误连续出现必须由监察看板展示。

## 测试策略

1. 领域测试覆盖员工归属领取、线程建立、镜像生命周期、通信同步和监察保护。
2. 引擎集成测试覆盖真实 worktree、等待恢复、发布冲突、成果登记、对话回写和用量记录。
3. 协调器测试覆盖上班、排空、自动规划、自动复盘、讨论打断和重启恢复。
4. 小说验收测试必须让 FakeExecutor 实际写章节文件，再验证事件 Task 和派生 Artifact。
5. Playwright 从创建小说公司开始，验证首个 Task 被执行、回复可见、成果可预览、复盘后必须手动继续。
6. Claude Code 真实冒烟测试作为本地可选验收，不在普通测试中消耗模型费用。

## 范围边界

本轮完成本地单用户长篇小说 MVP。多租户、支付、云端沙盒、PPT/视频编辑和多执行器市场不属于本轮，但执行器接口与 Artifact 处理器必须保留扩展边界。
