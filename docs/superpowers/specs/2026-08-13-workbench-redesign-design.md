# 工作台改版设计（Codex 式三栏 · 对话为中心 · 功能不丢）

**日期**：2026-08-13
**历史注记（2026-08-16）**：本设计为现行工作台蓝本；「和公司对话」的措辞已随公司退场统一为「工作台/项目对话」（公司级 API 保留）。
**动机**：软件规模过大、概念过多，用户使用直觉变差（不知道如何开始/怎么用/怎么配）。改版目标：收敛功能入口、降低上手难度，**让用户先用起来是第一位**，同时不丢失任何现有功能。

## 北极星

> **默认面只暴露核心动作：和公司对话 → 派活 → 看进展 → 审批。** 执行器/能力/权限/记忆/进化/外包都是"撞墙才出现"的 plumbing，不该是一级入口。

## 三项关键决策

1. **对话中心 = 公司级**：进公司即"和公司/第一负责人对话"（`ConversationPanel scope="company"`）；正式工作在项目内对话。
2. **一键启动 = 选模板 → 可选改名 → 开跑**：执行器/权限/首个项目/首任务/人设全自动套默认。
3. **配置进设置页，功能收左栏折叠组**：执行器/能力/权限 → 设置页；外包/进化/记忆/复盘/审批 → 左栏"回看/高级"折叠组（默认收起）。

## 目标信息架构（IA）

```
左栏（持久，按重要性）      中栏（默认=对话）            右栏（详情/过程）
───────────────            ────────────────            ───────────────
[公司/项目 切换器]          和公司/项目对话              对话派生的 Task 进度
───────────────            （ConversationPanel           工具调用 / 步骤
 对话 ← 默认落地             抬为中心 + 默认）            产出产物
 项目 → 中栏开任务看板
 员工 → 中栏开团队看板      点项目/员工时：              选中 Task → 详情+事件
 产物 → 中栏开产物库        该看板进中栏（对话让位）      选中员工 → 档案+记忆
───────────────
 回看（折叠）：审批/复盘/进化/记忆
 高级（折叠）：外包
 设置 → 完整设置页
```

**关键设计决定**：`conversation_message`（中栏对话）与 `task_message`（右栏任务详情）**不合并**——对应 Codex"聊天在中、详情在右"，避免数据迁移风险。

## 现状地基（已确认可复用）

- **对话闭环已通**：`ConversationPanel`（公司/项目 scope、@mention、user/assistant/system/event 四角色）+ `postUserMessage`（`src/server/domain/conversation.ts:101`）发消息即派发真实 Task → agent 干活 → 完成后引擎写回对话（`engine.ts:953-994`）。只差：抬为中心 + 实时流（现 4 秒轮询，`queries.ts:1034`）+ 内联步骤渲染。
- **模板引擎成熟**：schema 驱动蓝图（`src/shared/company-template.ts`）已实现——角色 + 组织/沟通图 + 工作流 + 知识模型 + 能力绑定 + 自动化。10 个内置模板（`template-registry.ts`）各含完整知识模型；LLM 模板架构师 + 内置兜底（`template-architect.ts`）；服务端目录 API `GET /api/company-setup/templates`。
- **人设库**：243 个人设跨 15 域（`persona-library.ts`），**但目前与模板断开**——模板员工只有字符串拼接的薄灵魂（`company-setup.ts:93`）。改版要接通。
- **三栏 shell 就绪**：`WorkbenchShell`（左/中/右 + ⌘K + ⌘B/⌘⇧B）+ WebSocket `RealtimeBus`（`realtime.ts`）。

## 现状问题诊断（改版要解决的）

1. **两套导航心智并存**：全局页扁平 9 项顶栏（`App.tsx:16-21`）vs 公司/项目页 3-pane 工作台——用户要在两套间切换。
2. **对话被埋**：是项目 4 个 view 之一（`ProjectPage.tsx:524`）+ 公司"活动"tab（`CompanyActivity.tsx:13`），非中心、非默认。
3. **四个重叠"回看"**：复盘 / 审批 / 反思记忆 / 进化优化报告——用户分不清。
4. **设置 hub-of-hubs + power-user 泄露**：~20 配置概念；常用卡默认暴露 3 档执行器 tier；自主进化/网络代理/NODE_EXTRA_CA_CERTS 对所有人裸露。
5. **首轮太技术**：`FirstRunWizard` 欢迎屏问 CLI 路径/API baseURL/模型 id/环境变量名。
6. **一键启动缺"启动包"**：向导强制名字+目标、强制逐员工绑执行器/权限、强制项目+任务三步——挡住"直接开跑"。
7. **术语混乱**：人才市场↔员工库（同页两名）；MCP/Bridge/Turbo/晨醒/白日梦 等 jargon 泄露到用户面；中英混排。

## 五批执行范围（详见 plan 文档）

- **批次 1 一键模板启动**：`company-starter.ts` + quick-start API + 人设接通 + 向导快速模式。
- **批次 2 三栏 IA**：UnifiedRail + 对话为中心 + 统一导航模型。
- **批次 3 收敛回看/plumbing/设置**：回看归组、plumbing 进设置/折叠、孤儿页定夺。
- **批次 4 对话体验升级**：`message.*` 实时事件 + 内联工具调用/步骤渲染。
- **批次 5 引导与文案**：FirstRunWizard 去技术化、术语统一、统一首轮引导。

## 不做（Out of Scope）

- token 级流式（工程量大、ROI 低；事件级实时已足够 Codex 感）。
- `conversation_message` 与 `task_message` 两表合并。
- 通用 CLI 配置管理器（已论证不划算）。
- 删除任何现有功能/route——只重组入口。
