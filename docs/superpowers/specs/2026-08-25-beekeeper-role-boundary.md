# 蜂群发起者可见性与养蜂人职责边界（一页定调）

状态：定稿（2026-08-25，随合并计划 R4-C 落地）
来源：合并计划 `2026-08-25-network-retry-progress-recovery-plan.md` C 项——蜂群多源可见性。本页是防偏航锚：谁可以放蜂、养蜂人管什么不管什么、发起者在哪可见。

## 现状规则（已正确，不改判定）

1. **放蜂权不经过养蜂人**：任何非控制面智能体返回 swarmPlan 均可直接落地（engine.ts:825-828）。控制面（swarm-worker/debater/debate-judge）永不自主。
2. **派遣分级**：负责人与养蜂人=全额四项限额；其他专家=小额自主额度（EXPERT_SWARM_LIMITS）——额度内直接放，超限或已有活跃蜂群 → [蜂群请示] 给负责人把关（engine.ts:842-859）。
3. **汇总归属**：汇总任务 assignee=发起树根派发者（swarm.ts:802），结果回发起者自己的树——不放给养蜂人。

## 养蜂人职责边界（防偏航）

养蜂人是**守门与救场岗**，不是必经路由、不是汇总接收方：

- 管：限额执行、防环检测、熔断（预算/失败率）、补蜂（失败自动修复）、蜂群回收。
- 不管：放蜂审批（那是负责人的事）、业务汇总（回发起者）、发起者意图判断。

任何「让所有蜂群都经过养蜂人」或「汇总统一交养蜂人」的提案都违背本页，需先修订本页再动代码。

## 发起者可见性（本批落地）

- `swarm_run.requester_agent_id` 已存库（20260816160000_swarm_requester.sql），此前界面上不可见。
- 本批补：`GET /api/tasks/:id/swarm` 返回 `requesterName`（agent_definition 解析）；蜂群拓扑卡显示「发起：N 工蜂 · 发起：某某」。
- 事件链：swarm.request-escalated 事件 payload 已带 requesterAgentId（实时可查）。

## 验收锚

- 派遣分级测试与蜂群树测试（既有）不回归。
- requesterName 字段在 API 响应中出现（null=系统/未知）。
