# 复盘：个人记忆跨项目污染与双层作用域隔离

**日期**：2026-08-19  
**影响范围**：干员个人记忆库（`agent_memory`）、项目上下文装配（`context.ts`）  
**状态**：已修复并建立作用域隔离防线  

---

## 1. 现象与问题回顾

在干员参与多个不同业务项目时，系统早期将个人工作记忆（Personal Memory）直接以全局无作用域方式注入所有项目的任务上下文。
导致以下问题：
1. **记忆污染与逻辑混乱**：A 项目（如外包审核）沉淀的私有业务假设被注入到 B 项目（如核心架构设计）中，造成干员决策偏差。
2. **上下文膨胀**：历史积累的跨项目记忆全量装配，加剧 Context Window 占用，加速触发 Compaction。

---

## 2. 根因分析

- **记忆分层模型不完备**：`agent_memory` 表最初未严格区分 `global`（通用技能/编码习惯/工具偏好）与 `project` / `workspace`（特定项目业务事实）的作用域标记。
- **装配逻辑缺乏过滤**：`context.ts` 装配个人记忆时未按当前 `projectId` 严格做过滤与优先级排序。

---

## 3. 改进措施与长效机制

1. **双层记忆作用域（Scope Hierarchy）**：
   - 个人记忆显式支持 `global`（全局通用）与 `project`（项目专用）两种作用域。
2. **严格上下文检索过滤**：
   - 装配上下文时，仅载入当前项目的 `project` 记忆及全局 `global` 记忆；杜绝其他项目的业务记忆注入。
3. **蓝图人设右侧栏记忆匹配（Blueprint Top Matches）**：
   - UI 与人设抽屉展示记忆归属与高匹配度经验，供用户直观校验与编辑。
